# 17 — Quality: how "zero bugs" is enforced

*Read this if: you're the orchestrator, any critic, or writing tests. "No bugs" is a process, not a wish — these are hard gates.*

## Test pyramid (all in CI; all green to exit any phase)

- **Unit (vitest):** schema validation edge cases, token→hex maps, URL policy, username rules, **`effectiveRole` + `can(role, action)` — every role × kyte-access × per-kyte-grant combination in the single ladder**, limit resolution (override vs default, 100 ceiling), reorder logic, deterministic moderation checks, LQIP/dimension math, HMAC sign/verify, OTP/invite/preview token + passcode hashing + attempt caps, schedule due-sweep selection with multiple pending (incl. skipping suspended kytes), import parsers (Linktree/Beacons/Bio.link fixture HTML → expected link sets; AI path mocked).
- **Integration:** every tRPC procedure against real docker Postgres/CH/Redis, with **authz denials as first-class cases** — wrong user, no session, VIEWER editing or reading analytics, EDITOR publishing, EDITOR touching domains, non-admin org member inviting org-wide, last-owner removal, cross-org kyteId probing (IDOR), non-admin hitting admin, mismatched-email invite accept, over-limit creates returning `LIMIT_REACHED`, **every mutating procedure on a SUSPENDED kyte returning `KYTE_SUSPENDED`**. **One-click revoke removes every grant.** Quarantine move + restore round-trips ([08-media.md](08-media.md)). Preview passcode right/wrong/rate-limited. `import.fromUrl` SSRF guards + proposal validation. Beacon → CH row assertions. Workers: moderation verdicts, revalidate retries, scheduled-publish fire/cancel/failure with 3 pending, og-image generation, invite/preview expiry sweeps. Email interface (console + smtp→mailpit). `POST /report` → `AbuseReport` row + admin action path; worker dead-letter/fail-open → `AdminAlert` row (and assert no admin-email code path exists).
- **E2E (Playwright, 375px + 1440px):** auth flows are tested for real (OTP via mailpit, mocked OAuth, passkey via virtual authenticator); everything else logs in via agent-mode `dev-login` ([24-agents.md](24-agents.md)) — one mechanism, fast suites. The golden path — signup via OTP (read the code from mailpit; BOTH type-it and magic-link) + Google + GitHub (mocked) + **passkey login (virtual authenticator)** → **onboarding to a LIVE page in one sitting (slug → prefilled name/avatar → skip links → published)** → edit → **avatar upload with crop/zoom + real progress states** → publish → static page correct → beacon lands → analytics render → username change (old 404s) → custom domain rewrite (hosts-file) → **second kyte → switcher (flat for solo, org tier appears with a second org) → invite teammate (accept from second account, strict email) → EDITOR blocked from publishing → one-click revoke strips access → kyte transferred between orgs (grants purged) → org caps trip the limit modal (10 kytes, 10 people, 3 owned orgs, 7 joined orgs, 250MB storage) → two schedules created (1st + 5th) → both fire in order → draft preview link gates on its passcode, renders, and revokes → links imported from a Linktree fixture page land in the draft after confirm** → phishing test profile suspended <60s → **editor shows the locked suspended state, mutations rejected, images 404 off the CDN** → admin approve → live again **with images restored** → admin Live view shows the traffic.
- **Visual regression:** ProfileView — 12 themes (9 legacy + 3 new) × {mobile, desktop} × {short, long-with-all-emoji-types, redirect, suspended, banned} — committed baselines; diffs must be intentional.
- **Degraded-mode boots** ([25-selfhost.md](25-selfhost.md)): start the stack without `CLICKHOUSE_URL` → one warning logged, no Analytics tab, admin shows the off-card, everything else green; start without `AWS_*` → uploads gone, default avatars offered, onboarding still reaches a live page; minimal-env boot (only the required vars) passes the golden path minus analytics/images.
- **Migration verification suite** ([18-migration.md](18-migration.md)) — its own gate.

## Defect policy

Any CONFIRMED critic finding or failing test = fixed before the phase exits. No "known issues" ship without an explicit founder waiver recorded in PROGRESS.md. Every bug fixed in Phases 3–5 lands with a regression test in the same change.

## Chaos bash (Phase 4)

Three parallel agents actively try to break the running app: absurd inputs (10k-char titles, RTL/zalgo/emoji-only usernames, `javascript:` URLs), double-clicks, publish/schedule races, invite-accept races (two accounts, expired tokens, revoked mid-accept), slow-network throttling, mobile touch flows, back-button abuse, expired session mid-edit, two tabs editing the same draft, kyte deleted while a member is editing it. Every find triaged to zero.

## Error-state completeness

Reviewers verify each page against the [14-design.md](14-design.md) checklist: loading, empty, error, offline, unauthorized. Missing state = bug.
